# Database Architecture & Data Model

## 1. Overview & Dual-Database Strategy

The platform employs a hybrid database strategy designed for zero-transaction distributed environments:

1. **Firebase Realtime Database (RTDB) — Authoritative Operational Store (`labddb-pro`)**:
   - Stores fast, authoritative state: student wallets, active print reservations, live locks, and global pricing configurations.
   - Operated entirely via HTTP REST and atomic Compare-And-Swap (CAS) via HTTP ETags.
   - Enforces the 20 financial invariants with zero-cost read replicas and microsecond latency.

2. **Cloudflare D1 (Serverless SQLite) — Immutable Audit & Analytics Store**:
   - Stores append-only history of every admin action, student authentication, print job archive, and financial ledger transaction.
   - Facilitates fast multi-dimensional SQL querying, search, pagination, and margin analytics without impacting RTDB throughput.

3. **Cloudflare R2 — Document Object Storage (`labddb-covers`)**:
   - Stores binary PDF covers generated by students with structured keys and metadata tags.

## 3. Cloudflare D1 SQL Schema

```sql
-- D1 Migration: schema.sql

CREATE TABLE IF NOT EXISTS audit_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  action TEXT NOT NULL,
  actor_uid TEXT NOT NULL,
  actor_email TEXT NOT NULL,
  target_uid TEXT,
  details TEXT,
  ip TEXT,
  user_agent TEXT
);

CREATE TABLE IF NOT EXISTS user_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  uid TEXT NOT NULL,
  email TEXT NOT NULL,
  display_name TEXT,
  action TEXT NOT NULL,
  metadata TEXT,
  ip TEXT,
  user_agent TEXT
);

CREATE TABLE IF NOT EXISTS print_jobs_archive (
  job_id TEXT PRIMARY KEY,
  uid TEXT NOT NULL,
  email TEXT NOT NULL,
  roll TEXT,
  courseCode TEXT,
  title TEXT,
  tool TEXT,
  pages INTEGER NOT NULL,
  copies INTEGER NOT NULL,
  color INTEGER NOT NULL,
  price REAL NOT NULL,
  unit_price REAL NOT NULL,
  uprint_estimate REAL,
  actual_cost REAL,
  otp TEXT,
  record_id TEXT,
  status TEXT NOT NULL,
  r2_pdf_key TEXT,
  created_at INTEGER NOT NULL,
  expires_at INTEGER,
  settled_at INTEGER,
  released_at INTEGER,
  device_id TEXT,
  failure_reason TEXT
);

CREATE TABLE IF NOT EXISTS wallet_ledger_archive (
  id TEXT PRIMARY KEY,
  uid TEXT NOT NULL,
  type TEXT NOT NULL,
  amount REAL NOT NULL,

  job_id TEXT,
  note TEXT,
  by_uid TEXT,
  method TEXT,

);

CREATE INDEX IF NOT EXISTS idx_audit_timestamp ON audit_logs(timestamp);
CREATE INDEX IF NOT EXISTS idx_audit_action ON audit_logs(action);

CREATE INDEX IF NOT EXISTS idx_print_jobs_uid ON print_jobs_archive(uid);
CREATE INDEX IF NOT EXISTS idx_print_jobs_status ON print_jobs_archive(status);
CREATE INDEX IF NOT EXISTS idx_wallet_ledger_uid ON wallet_ledger_archive(uid);
```

## 4. Key Encodings & Escaping Rules

- **Firebase Path Keys**: Firebase Realtime Database path segment keys cannot contain `.`, `$`, `#`, `[`, `]`, or `/`.
  - Filenames are converted to safe keys via `fileKey(filename)`:
    ```javascript
    function fileKey(filename) {
      return String(filename).replace(/[.$#[\]/]/g, '_');
    }
    ```
  - Emails in `adminIndex/byEmail` are converted via `emailKey(email)`:
    ```javascript
    function emailKey(email) {
      return String(email).toLowerCase().replace(/[.$#[\]/@]/g, '_');
    }
    ```
